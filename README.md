# Чистый След

## О проекте

**Платформа для мониторинга экосистем с участием волонтёров и сотрудников ООПТ. Проект разработан в рамках хакатона.**

## Быстрый старт

Что нужно установить
Единственное, что потребуется — Docker Desktop. Скачать можно с официального сайта docker.com. После установки нужно запустить Docker и дождаться, когда в статусе появится надпись "Engine running".

## Как скачать проект

Откройте терминал или командную строку и выполните:
git clone https://gitverse.ru/hackrus.experts/kosmo-rostov_glo_65.git
cd kosmo-rostov_glo_65
Если Git не установлен, проект можно скачать ZIP-архивом со страницы репозитория на GitVerse и распаковать в любую папку.

## Как запустить

В папке с проектом выполните одну команду:
docker-compose up --build
После этого компьютер сам поднимет базу данных, запустит бэкенд и фронтенд. Никаких дополнительных действий не требуется.

## Как открыть в браузере

После запуска в консоли появятся адреса:

Фронтенд: http://localhost:3000
Бэкенд API: http://localhost:8080

## Тестовые пользователи

Для проверки работы можно использовать готовые аккаунты или зарегистрироваться самостоятельно.
Скаут: scout@example.com, пароль password123
Инспектор ООПТ: oopt@example.com, пароль password123

**Если эти пользователи отсутствуют в базе, их можно создать через интерфейс регистрации.**

## API

**Бэкенд предоставляет REST API. Все запросы, кроме регистрации и входа, требуют JWT-токен. Токен передаётся в заголовке Authorization: Bearer <токен>.**

### Доступные эндпоинты:

- POST /api/auth/register — регистрация пользователя
- POST /api/auth/login — вход в систему, возвращает токен
- GET /api/user/profile — получение профиля текущего пользователя
- GET /api/missions — список всех миссий
- GET /api/missions/:missionId — детали одной миссии
- POST /api/reports — создание отчёта об аномалии
- GET /api/reports — список отчётов (с фильтром по статусу)
- PATCH /api/reports/:reportId/status — изменение статуса отчёта (только для инспекторов)

## Структура проекта

В корне проекта находятся две папки: backend и frontend. В папке backend лежит Go-сервер с хендлерами, моделями и middleware. Там же находятся файлы go.mod, go.sum и Dockerfile для сборки. В папке frontend находится Next.js-приложение с исходниками, статикой и собственным Dockerfile.
В корне также лежит docker-compose.yml, который запускает все сервисы вместе, и файл .gitignore для исключения служебных файлов.

## Как проверить работу

Самый простой способ — открыть в браузере http://localhost:3000 и зарегистрироваться.

Для проверки через командную строку можно выполнить несколько запросов.

Регистрация нового пользователя:

curl -X POST http://localhost:8080/api/auth/register -H "Content-Type: application/json" -d "{"email":"test@example.com","password":"password123","name":"Тест","role":"scout"}"

### Вход в систему и получение токена:

curl -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" -d "{"email":"test@example.com","password":"password123"}"

### Получение списка миссий с токеном:

curl -X GET http://localhost:8080/api/missions -H "Authorization: Bearer <ваш_токен>"

## Возможные проблемы

- Если при попытке открыть localhost:3000 или localhost:8080 ничего не происходит, нужно убедиться, что Docker Desktop запущен и контейнеры работают. Проверить это можно командой docker ps.

- Если база данных не подключается, возможно, PostgreSQL внутри контейнера не успел инициализироваться. В этом случае помогает перезапуск: docker-compose down и затем docker-compose up --build.

- При ошибке "Invalid token" или "Unauthorized" токен мог истечь. Достаточно войти заново и получить новый.

- Если фронтенд не собирается с ошибкой "Module not found", проверьте, что в папке frontend есть папка mocks с файлами missions.json, mission_details.json и reports.json.

_Команды для управления проектом:_

Запуск всех сервисов: docker-compose up --build
Запуск в фоновом режиме: docker-compose up -d
Остановка: docker-compose down
Остановка с удалением данных базы: docker-compose down -v
Пересборка без использования кеша: docker-compose build --no-cache

## Технологии

Бэкенд написан на Go с использованием веб-фреймворка Gin и ORM GORM. Для аутентификации используются JWT-токены, пароли хешируются с помощью bcrypt. В качестве базы данных используется PostgreSQL. Фронтенд написан на Next.js с React и TypeScript. Вся инфраструктура упакована в Docker-контейнеры и управляется через Docker Compose.
